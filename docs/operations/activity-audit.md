# Workspace activity audit (#266)

The activity page stores new project, member, translation, glossary, exclusion, API key, webhook, billing setting, and workspace changes as tenant-scoped `AuditEvent` rows. There is no historical backfill. Each row records the workspace, optional project and actor, a stable action code, timestamp, and bounded metadata. Metadata accepts only counts, language/role/status/kind/source labels, and opaque IDs. It must never contain translation content, URLs, email addresses, credentials, webhook secrets, payment details, or arbitrary request bodies.

## Mutation coverage

| Family | Recorded mutations | Writer paths | Coupling |

Read-only requests, previews, failed writes and unchanged saves do not create activity rows. Repeating page-view activation is an explicit consent renewal: it refreshes the consent timestamp and records `project.page_views_consent_renewed`. Repeating a disabled page-view setting does not record an event. Automatic background processing outside the listed accepted mutations is not presented as a user action. New writers must add a bounded action label and a tenant/rollback integration check before joining this matrix.

Project and database-only settings changes write the event in the same transaction as the change, so failure rolls both back. External billing provider changes cannot share a database transaction: the event is appended after provider success. A failed database append after provider success requires operational reconciliation; do not claim that the two systems commit atomically.

Only workspace `OWNER` and `ADMIN` members can read the activity view. Every query is constrained by `organizationId` and rechecks membership in the query helper. The page accepts date range, actor, project, and category filters, including IDs from retained events for former members and projects. Date selection follows the page's Europe/Vienna display timezone, including daylight-saving transitions. It displays 100 rows per page with a tenant-scoped cursor to reach older events on the same day. CSV export contains exactly the displayed page and bounded metadata, with UTC timestamps and spreadsheet formula prefixes escaped. Follow the older-events link to export further pages; there is no bulk export endpoint. Project deletion preserves the opaque project ID in the event until expiration; user deletion removes the actor relation. An actor's current name is shown only while they remain a workspace member or belong to a project still in this workspace; otherwise the view uses the retained opaque actor ID. Project transfer detaches source-workspace events from the live project relation before moving the project; the transfer-out event keeps the project snapshot ID for filtering, while source readers cannot see later destination project names.

The authenticated daily `/api/cron/audit-retention` job deletes audit rows older than **365 days**. Workspace deletion cascades its audit rows immediately. The retention clock is the event creation timestamp in UTC. Keep the cron scheduled and monitor failures; there is no claim that backups are purged by this job. A privacy or support export beyond the UI needs a separate authorized process.

Release order: apply the Prisma schema on the target database, deploy the event writers and reader, then verify one real authorized mutation appears in the correct workspace and is absent to a member of another workspace. CI integration tests must use an isolated local PostgreSQL database and cover tenant isolation, rollback, and retention.
