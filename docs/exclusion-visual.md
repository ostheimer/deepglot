# Visual exclusion builder

Project managers open **Settings → Exclusions → Select on page**, enter a path on the project's configured public domain, and click an element in the preview. The preview displays the exact class or ID rule and the number of matches on that page before saving. Saving uses the existing exclusion CRUD route, so project management authorization, tenant scope, duplicate handling, and WordPress settings synchronization are shared with manually entered rules. The preview request requires the same management access. A translator or manager of another project cannot load this page through the API.

The builder proposes only a single literal ID or class token that the current WordPress runtime can apply. It tries the clicked element's ID first, then its classes. The token must be unique in the loaded page and pass a conservative stability filter; generic layout/state tokens, structural page roots, long hexadecimal tokens, and elements covering more than 100 descendants, 3,000 text characters, or half the page text with multiple descendants are refused. CSS escaping is used for the preview query; the saved value is the literal token, which is how the WordPress plugin compares `id` and `class` attributes. The builder does not pretend that a compound selector or a URL-specific CSS rule is supported. A selected class or ID applies **on every page in the project where it occurs**, after the next plugin synchronization. The page-level uniqueness check cannot prove site-wide uniqueness or future DOM stability, so managers should choose semantic IDs/classes and inspect translated pages after saving.

The page loader accepts only a path, uses the configured project origin, rejects private or reserved DNS answers, pins the network request to the validated address, follows no redirects, accepts only HTML, and caps the response at 1 MiB and eight seconds. The server request sends no project credentials. The iframe has scripts and form submission disabled. Its content security policy allows images, styles, and fonts only from the project origin. Only a public page can be previewed. A page requiring authentication, redirecting, or relying on JavaScript to render its content is unavailable to this builder.

The exclusion order remains the WordPress runtime contract: URL patterns are checked first, then regexes, before any translation output buffer starts. Either route match skips translation for the complete source route. On a route that remains translatable, class and ID exclusions protect matching element subtrees, including supported user-facing attributes and mapped media, before text is sent to a provider. CSS rules do not override a URL or regex route exclusion. A visual rule is simply a CSS class or ID rule in this same contract. URL wildcard and regex syntax are described in [exclusion-csv.md](exclusion-csv.md).
