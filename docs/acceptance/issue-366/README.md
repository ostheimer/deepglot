The 0.12.12 package is now public and the updated GlotPress candidates have been submitted. See the [release and catalog readback](release-01212.md) for the separate GitHub, WordPress.org, installer, and translation statuses. The historical assessment below describes the state before publication.

Checked on 2026-10-05 against plugin source based on GitHub `main` commit `4dff0de2bb75543920c1eb86ccd9034a67914bb7` (the last public WordPress.org plugin release was 0.12.11). This change is a proposed source/catalog update, not a WordPress.org release or GlotPress import. The issue is referenced, not automatically closed.

The [review snapshot](https://translate.wordpress.org/projects/wp-plugins/deepglot/) is distinct from this unpublished branch.

Compare this candidate to the actual post-release public Readme originals before any import; it is not currently an import or public approval.

## Runtime contract and reproduction

The isolated `deepglot366` WordPress 7.1 fixture used the worktree plugin source mounted read-only by `wordpress-plugin/docker-compose.yml`. It installed real old official 0.12.11 [de_DE](https://downloads.wordpress.org/translation/plugin/deepglot/0.12.11/de_DE.zip) and [de_DE_formal](https://downloads.wordpress.org/translation/plugin/deepglot/0.12.11/de_DE_formal.zip) files under `wp-content/languages/plugins`. There was no public `sv_SE` pack; Swedish came from the bundle. Core locales were installed separately. The fixture is disposable and is removed after testing.

To reproduce, use an isolated Compose project and install WordPress plus the plugin, then copy the downloaded ZIP contents into the fixture's `wp-content/languages/plugins` and install the `de_DE`, `de_DE_formal`, and `sv_SE` core locales:

```sh
docker compose -p deepglot366 -f wordpress-plugin/docker-compose.yml up -d
docker compose -p deepglot366 -f wordpress-plugin/docker-compose.yml run --rm cli wp core install --url=http://localhost:8090 --title='Deepglot Test' --admin_user=admin --admin_password=admin --admin_email=admin@example.com --skip-email
docker compose -p deepglot366 -f wordpress-plugin/docker-compose.yml run --rm cli wp plugin activate deepglot
for locale in de_DE de_DE_formal sv_SE; do docker compose -p deepglot366 -f wordpress-plugin/docker-compose.yml run --rm cli wp language core install "$locale"; done
for locale in en_US de_DE de_DE_formal sv_SE; do
  docker compose -p deepglot366 -f wordpress-plugin/docker-compose.yml run --rm -e DG_TEST_LOCALE="$locale" cli wp eval 'add_filter("determine_locale", fn() => getenv("DG_TEST_LOCALE")); echo getenv("DG_TEST_LOCALE") . ": " . __("Language switcher", "deepglot") . " | " . __("Select highlighted text on the page.", "deepglot") . PHP_EOL;'
done
```

Observed PHP output: `en_US: Language switcher | Select highlighted text on the page.`, `de_DE: Sprachschalter | Wähle einen markierten Text auf der Seite.`, `de_DE_formal: Sprachschalter | Wählen Sie einen markierten Text auf der Seite.`, and `sv_SE: Språkväljare | Välj den markerade texten på sidan.` The en_US case returns English without loading an English WordPress language pack. A second en_US probe explicitly unloaded `deepglot` and blocked subsequent text-domain loading via `override_load_textdomain`; it still returned `Language switcher | Select highlighted text on the page.` With site locale en_US and an admin `determine_locale` override to de_DE_formal, the new Visual Editor prompt was formal German. An active `switch_to_locale()` similarly used the switched locale. A simulated current official PHP pack translation for the new “Language switcher” key won over the bundle, while its missing new Visual Editor key fell back to the bundle. The plugin does not change any saved options or production language packs.

For the block editor, the test called `load_script_textdomain('deepglot-switcher-block', 'deepglot', DEEPGLOT_PLUGIN_DIR . 'languages')` after applying the `determine_locale` override. The old official JSON files coexisted with bundled JSON and returned the new ID `Deepglot language switcher` as `Deepglot Sprachschalter` for German, `Deepglot Sprachschalter` for formal German, and `Deepglots språkväljare` for Swedish. To test a future current official JSON, a temporary copy of the old de_DE JSON was given the new key `Deepglot language switcher: ["Aktuelle offizielle JS-Sprachwahl"]`; the returned catalog kept this official value and retained bundle-only new keys. The original old JSON was restored immediately. PHP and JS precedence are separate paths: PHP falls back only when core returns the original; JS merges bundled current keys with official keys overriding them.
