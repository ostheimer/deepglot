The runtime contract uses the existing `ProjectLanguage.id` as a per-target generation. WordPress validates the complete generation map with the active targets before applying any project field. A changed ID advances the target cache epoch, purges known page caches, and reconciles queued translation and URL work; an unchanged ID preserves the cache and queue. Pausing and reactivating an existing row preserves its ID. An invalid generation map preserves the prior source/target/visible/automatic/generation/version fields and cache epoch. A pre-lifecycle SaaS runtime snapshot without the new keys still yields the legacy visible and automatic target behavior.
