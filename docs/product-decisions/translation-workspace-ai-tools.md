# Workspace AI suggestions and selected search/replace (#257)

## Search and replace

The editor sends 1–100 explicit selected segment IDs and versions. Preview is read-only and returns each before/after string plus a SHA-256 fingerprint bound to project, actor, selection, versions, literal search, replacement and the reviewed-text choice. Apply locks the project, target language, memberships and sorted rows, re-reads permissions, glossary and content, recomputes the preview, then updates all rows or none. A stale row, changed scope or changed glossary fails before any translation write. Every changed row becomes manual, resets approval, records a full content revision, manual batch accounting and the existing manual-update webhook. Dependency cache handling follows the shared runtime contract.

Only reported text is eligible. Unknown, mixed media/link and other types require separate handling. Manual or approved text is excluded by default; an explicit include control marks each reviewed row and the status reset in preview. Placeholders recognized by the literal grammar, URLs, HTML tags, entities, email addresses and protected glossary terms must remain identical. An absent search term in any selected row is an error, never a silent partial application. No provider call is made.

## AI suggestion boundary

Improve, Rephrase and Shorten are available from the existing manual editor for reported text. Preview re-reads the effective project provider/model, current monthly quota use and the conservative input/output units and monetary ceiling from the approved organization and project policies. Inactive enforcement is explicitly `previewOnly` with `allowed: null`; it does not authorize this new editor provider action. A separate Run click is required before any provider work. DeepL is rejected because this rewrite action is unsupported. A reconnect-required project provider is blocked; runtime fallback providers are disabled for this action. The trusted rewrite action is supplied to the provider adapters as a system instruction; project content and instructions remain untrusted context.

The execution rechecks actor, language, row version, settings and glossary before dispatch. One segment is bounded to 10,000 characters. The existing organization-wide monthly usage and hourly velocity guards apply. Monthly usage and a durable `DISPATCHED` idempotency marker commit together immediately before provider HTTP; the marker cannot be reclaimed after a crash, even if its lease or retention clock expires. Known rejection before that boundary releases the velocity reservation and charges no monthly usage. After dispatch, an unusable response, revoked access or changed glossary/provider leaves the charged usage and a terminal unavailable receipt; replay cannot silently buy another call. A completed success replays the same suggestion after fresh permission and version checks. Provider adapters execute one configured call without runtime fallback or retry. The response is validated against literal placeholders, URLs, HTML tags, entities, emails and protected glossary terms. A rejected output is never stored. A valid result appears in a separate suggestion preview; only Use suggestion copies it into the draft, and only the existing manual save with its original CAS version makes it authoritative. Concurrent row edits still fail that save. No automatic approval or direct AI write occurs.

The preview is read-only. The Run path repeats authorization and atomically commits quota, an irreversible dispatch marker and the approved spend reservation before HTTP. Successful usage settles against a provider receipt; unknown usage retains its conservative hold. The configured provider key may incur external charges; this feature grants no implicit platform credits and never activates an organization budget. The separate bounded WordPress source-page snapshot supports absence **only within freshly and completely captured server-rendered pages**. It does not infer global website inactivity from last-seen timestamps, sitemap URLs or cache statistics; dynamic or uncaptured pages remain unknown. #320's deferred crawler is not recreated by this feature.

## PDF provider action

The existing PDF action gets a read-only preview from the exact parsed source pages and bounded project context sent to dispatch. It shows monthly word use and, when owner-approved policies exist, a conservative price ceiling for every possible root, configured fallback and count-mismatch singleton attempt. With active enforcement, an unapproved provider/model blocks the complete action; a partial quote is never presented as the full ceiling. With enforcement off, `allowed: null` is an estimate only and the existing PDF action remains available after the explicit Run click under current project settings. File digest, target language, project/organization, actor, effective provider chain, settings, budget revisions, request key and expiry bind the active preview. Run checks that fingerprint and the full quote again before work. Directly before each budgeted provider HTTP attempt, an organization-to-project-locked transaction checks the current settings, glossary and approved examples and writes a spend reservation. A changed input requires a fresh preview. Once a budgeted job key reaches a provider, a same-key retry cannot buy a second call, even if output generation fails. PDF generation remains the existing text-only reflow, not preservation of the source layout.
