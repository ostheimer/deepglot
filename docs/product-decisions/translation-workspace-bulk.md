# Translation workspace bulk workflow

The first bulk slice of issue #257 applies only to assignment and review state. Managers can assign or unassign selected segments, submit assigned segments, approve or return segments in review, and reopen approved segments. A translator can submit only segments currently assigned to their project membership and within their permitted target language. Content editing, deletion, AI actions and search-and-replace are outside this batch endpoint.

The workspace selects explicit rows on the currently visible page. Filter or page changes clear the selection. The server accepts 1–100 distinct IDs, a single action and the status, assignee and `updatedAt` observed for every row. It never interprets a filter as permission to mutate all matching rows. A target assignee must be an eligible member of the same project for every selected language. All source and target languages must still be active.

`POST /api/projects/{projectId}/translations/bulk` validates the authenticated project access and input. Inside one PostgreSQL transaction it locks the project and selected translation rows, rechecks the actor's current project and organization memberships, validates every expected snapshot and existing workflow transition, then writes all rows. On any missing, stale, unauthorized or invalid row, the transaction rolls back and returns an error; no partial success is reported. A successful response is `{ "updated": <count> }`. The UI reloads after success or failure; if the response cannot be confirmed, it asks the user to inspect the refreshed list before retrying. Workflow mutations do not edit translation text, invalidate caches, emit content webhooks or change billing usage.

The endpoint adds no schema migration. Acceptance covers pure action mapping, PostgreSQL rollback and authorization cases, and a browser path through selection, assignment, submission and approval. The broader issue remains open for history, AI editing, search-and-replace, authoritative inactivity and complete parity.
