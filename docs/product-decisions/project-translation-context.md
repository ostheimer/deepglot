# Project translation context (#260)

Project managers can save a website description, tone, audience, and additional instructions in the language-model settings. They can independently enable glossary rules and approved or manually edited translations as model context. The setting API uses `userCanManageProject` for GET, PATCH, and the suggestion POST. Provider API keys remain encrypted in `ProjectSettings` and never appear in its response or the context builder.

The suggestion button calls POST only after a manager clicks it. POST constructs a local draft from the project's existing name, domain, website type, and industry; it performs no provider call or database write. The user must review and save the draft with PATCH. All visible German text uses umlauts. For locales whose new context labels have no reviewed translation yet, the explicit catalog entry falls back to English.

`/api/translate` retains its cache, exact manual translation, translation-memory, glossary protection, quota, velocity, provider selection, and fallback sequence. Only uncached new strings get the bounded project context. The route reads current settings again before provider dispatch and selects at most 12 same-project, same-language approved or manually edited examples. No other application endpoint dispatches `translateTexts`; the static-message generation script uses that function without a project.

The context limit is 4,000 characters per provider request. Stored fields have separate input limits (description 1,200; tone 160; audience 300; instructions 1,000). Control characters are flattened. Prompt order and stated precedence are: preserve variables, placeholders, HTML, and URLs; apply glossary protection and exact manual/cache translations; use selected glossary terms and approved examples as guidance; then apply tone, audience, and additional instructions within those constraints. The builder reserves room for the saved instructions before fitting glossary and example lines, and reserves example room when both switches are enabled. OpenAI-compatible providers, Gemini, and DeepL receive the same context string through their existing adapters. Mock mode remains deterministic and makes no external call.

Apply `scripts/sql/translation-project-context.sql` before deploying the Prisma reader to Preview and Production. It adds nullable text columns and two `false` default switches to `ProjectSettings`; it does not rewrite translation rows. The SQL is repeatable. Compare the target schema read-only after application. Never use a destructive production schema push for this change. Local contract tests use provider fixtures and must not make paid provider calls.
